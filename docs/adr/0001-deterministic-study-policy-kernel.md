# ADR-0001: Deterministic study-policy kernel

- Status: Accepted
- Date: 2026-08-15
- Research: `../research/representation-architecture.md`

## Context

The engine must execute versioned learning protocols, evaluate temporal and uncertain policy rules, preserve learner-owned cognition, and make every transition auditable. A single canonical graph does not adequately model event history, uncertainty, conflict resolution, provenance, or deterministic replay.

## Decision

Use a SQLite-first hybrid architecture:

- append-only events and typed evidence/artifact links are canonical history;
- protocol definitions are immutable, versioned, project-owned statechart-like graphs;
- protocol instances pin an exact protocol version;
- policy definitions use a deliberately limited typed `ConditionAST`;
- sessions/evaluations pin an exact versioned policy bundle;
- policy evaluation returns `matched | not_matched | uncertain`;
- a deterministic conflict resolver selects at most one primary learner-facing intervention;
- explanation traces are generated by deterministic evaluators, not invented by an LLM;
- learner knowledge nodes/edges remain a separate relational model and graph projection;
- Obsidian, XState, RDF, graph stores, Datalog, Rete, and CEP are optional adapters/backends, not canonical storage.

Do not introduce a graph database, generic rule engine, or XState runtime in the first implementation.

## Required event properties

Canonical events require:

- stable sequence/order;
- actor;
- provenance reference;
- payload hash;
- occurred and recorded timestamps;
- causation and correlation references;
- schema version;
- typed references to session, target, protocol instance, attempts, evidence, and artifacts where applicable.

Corrections use superseding/compensating events rather than mutation of canonical history.

## Evidence and transitions

The deterministic core must never accept LLM-provided booleans such as `targetRubricPassed: true` as sufficient evidence. Guards query real attempt, assessment, artifact, contamination, and source-evidence IDs from SQLite.

Generic evidence links do not replace domain entities. Attempts, assessments, artifacts, source claims, authorship, and contamination retain typed schemas and relations.

## Required additional entities

- `policy_bundle` and versioned bundle membership;
- `policy_activation`/pinned evaluation context;
- `intervention_template`;
- `protocol_migration`;
- `operation_attempt`;
- `artifact_authorship`;
- dimension/target-scoped contamination state.

## Uncertainty

Telemetry absence is not proof of cognitive absence. Conditions distinguish recorded absence, explicit negative observation, and unknown observation coverage. Low-confidence or unobservable cases produce `uncertain`, not a behavioral diagnosis.

## Consequences

Benefits:

- deterministic replay and auditability;
- no second database service;
- replaceable execution adapters;
- explicit provenance and policy versioning;
- protocol, policy, and learner graphs remain separate;
- graph projections remain available without graph canonicalization.

Costs:

- the project owns a small protocol metamodel, ConditionAST evaluator, validator, conflict resolver, and migration discipline;
- authoring tools may be needed if rule volume grows;
- temporal queries and projections require profiling and indexes.

## Implementation order

1. Freeze legacy semantics and create golden sessions.
2. Introduce real transactional SQLite migrations.
3. Add normalized append-only events with dual-write/replay checks.
4. Add immutable policy definitions and pinned policy bundles.
5. Implement a minimal tri-valued ConditionAST and explanation trace.
6. Activate two antipattern rules and deterministic one-intervention conflict resolution.
7. Replace boolean transition evidence with typed persisted IDs.
8. Introduce the versioned protocol metamodel and move the legacy state graph into a legacy protocol definition.
9. Add operation-level authorship and contamination.
10. Import additional XML registry rules only after deterministic validation and human review.

## Falsification

Reconsider individual adapters/backends only after profiling or real protocol requirements demonstrate that:

- indexed SQLite temporal evaluation is too slow;
- rule matching requires Rete/Datalog/CEP;
- protocols require extensive nested concurrency/history semantics;
- learner graph workload is dominated by large multi-hop traversal;
- safe rule authoring requires a decision-table/DMN projection.

The decision-matrix score in the research report is supporting analysis, not empirical proof.
